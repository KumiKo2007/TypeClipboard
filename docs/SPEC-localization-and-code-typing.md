# TypeClipboard 中英文与代码模拟输入重构规格说明

**状态：** 已确认（实施中）

**日期：** 2026-10-02

**目标项目：** `/Users/Admin/Desktop/TypeClipboard`（macOS 13+，Swift 6.2，SwiftUI）

## 1. 目标与验收对象

TypeClipboard 将可编辑缓冲区中的纯文本模拟为键盘输入。本次改进有两个目标：

1. 让应用可在英文与简体中文之间切换。
2. 让多行代码在网页代码编辑器中按原有内容输入，并能在倒计时或输入过程中可靠取消。

首要人工验收对象是用户截图中的学习通“AI 实践”C++ 代码编辑器，涵盖作业和考试场景。其他网页的多行文本框与代码编辑器尽可能通过可选输入模式兼容。**“兼容”以明确测试过的编辑器和模式为准，不承诺所有网页都会接受或保留合成按键。**

## 2. 能力划分

| 模块 ID | 职责 | 依赖 |
|---|---|---|
| `localization` | 语言选择、持久化、界面与文档翻译 | — |
| `typing-fidelity` | 多行、空行、缩进、末尾换行与网页输入模式 | — |
| `typing-cancellation` | 全局实体按键取消、按键拦截与输入事件清理 | `typing-fidelity` 的输入任务生命周期 |

建议验证顺序：`typing-fidelity` → `typing-cancellation`；`localization` 可独立验证。这里是需求边界，不限定代码必须拆成三个模块。

## 3. 用户流程

1. 用户捕获剪贴板内容或在应用缓冲区编辑代码。
2. 用户选择语言和输入模式。输入模式由用户手动选择并保存；应用不读取浏览器网址，也不自动识别网站。
3. 用户点击“开始输入”，在倒计时内将焦点放到目标网页编辑器。
4. 应用按缓冲区顺序模拟输入。代码中的换行使用所选模式对应的真实按键组合；普通字符、空格和 Tab 不被静默替换。默认不额外追加 Return。
5. 倒计时或输入期间，用户按下新的实体键盘按键即取消；该取消键不进入目标网页。
6. 应用报告“发送完成”“已取消”或具体错误。完成状态不声称已验证网页中的最终文本，用户自行核对。

## 4. 功能需求

### 4.1 中英文切换

| ID | 要求 |
|---|---|
| L01 | 提供“自动（跟随 macOS）”“English”“简体中文”三个选项。 |
| L02 | 手动选择后立即更新当前界面，并在重新启动应用后保持；“自动”随系统语言选择英文或简体中文。 |
| L03 | 翻译所有用户可见的界面标题、按钮、菜单、状态、计数单位、权限引导和错误信息；动态数值与复数表达自然。 |
| L04 | README 和 GUIDE 提供中英文说明，且与新的默认行为、输入模式及取消方式一致。 |
| L05 | 原有英文用户继续得到完整英文界面；未提供的系统语言回退到英文。 |

### 4.2 代码内容准确性

| ID | 要求 |
|---|---|
| T01 | 正文内的每个换行必须触发所选模式的实际换行按键，而非仅把换行 Unicode 字符附着到普通按键事件。 |
| T02 | 保留行顺序、空行、行首与行尾空格、Tab、普通字符以及原文末尾是否有换行。不静默将 Tab 转为空格，也不自动增删缩进。 |
| T03 | CRLF、LF 和单独 CR 输入可统一为目标编辑器中的一处换行；验收比较时 CRLF 与 LF 等价。除此以外，字符和缩进保持一致。 |
| T04 | 提供至少“Enter 换行”和“Shift+Enter 换行”两种模式；用户手动选模式，并能保存常用配置，例如“学习通”和“通用”。不自动读取网页 URL。 |
| T05 | “输入后额外按 Return”默认关闭，仍可由用户显式开启；原文自带的末尾换行始终按原文输入，与该选项独立。 |
| T06 | 对已知的权限、事件创建或发送失败立即停止，给出可理解的错误提示。不把“事件已发送”误报为“已核对网页内容”。 |

### 4.3 取消

| ID | 要求 |
|---|---|
| C01 | 从倒计时开始至输入完成前，任何新按下且系统可观察到的实体键盘按键都取消任务，包括单独的 Shift、Control、Option、Command。启动前已按住的键不触发取消。 |
| C02 | 取消键及其对应的释放事件不进入目标网页；应用自己生成的输入事件不能触发取消。 |
| C03 | 取消后不再发送后续正文或额外 Return；所有已经发送的按键按下事件都必须配对发送释放事件，避免按键或修饰键保持按下状态。 |
| C04 | 原有应用内“取消输入”按钮继续有效。无论目标浏览器是否位于前台，用户都能通过实体按键取消。 |
| C05 | 全局按键监听仅在任务活动期间启用，结束、取消或失败后立即清理。若无法建立可靠监听，不得在缺少该保护的情况下悄悄开始输入；应告知用户并阻止启动。 |

## 5. 验收样例

### A. 多行代码

缓冲区为以下文本，第二行为空行，第三行以四个空格缩进，最后一行后没有换行：

```cpp
#include <iostream>

    int main() { return 0; }
```

在受控测试编辑器及学习通目标编辑器中，选择有效的换行模式后，输出应有相同的三行、空行及四个空格缩进，且不得多出第四行。另用含有真实 Tab、末尾换行和非 ASCII 字符的样本分别验证原字符保留。若目标网页自行改写内容，此项记录为目标兼容性限制，不得把发送完成当作内容一致的证明。

### B. 网页输入模式

同一段两行文本分别用 Enter 与 Shift+Enter 模式测试：所选组合须与发出的键盘事件一致；切换并保存模式后，重启应用仍保留选择。学习通作业和考试编辑器需要人工确认适用模式；无法访问的受登录保护页面不以本地模拟结果代替真人验收。

### C. 末尾 Return

默认设置下，输入 `abc` 只发送 `abc`；输入 `abc\n` 则发送一次原文末尾换行。显式开启“额外 Return”时才再发送一次 Return。

### D. 取消

在倒计时和实际输入中，分别按字母键和单独 Shift：任务均停止，取消键不出现在目标内容中，已按下的合成键均释放。切到浏览器后同样有效。正常任务完成后，键盘不再被应用拦截。

### E. 语言

三个语言选项逐一切换并重启应用：界面、菜单、权限提示、计数、发送与取消状态均使用所选语言；系统语言不支持时显示英文。

## 6. 验证策略

- **自动测试：** 使用现有 XCTest。将文本拆分为输入事件的逻辑与系统事件发送分开测试，覆盖 LF/CRLF/CR、空行、Tab、尾换行、额外 Return、两种换行模式和取消时的按下/释放配对。验证语言选择持久化、主要状态信息及任务取消状态。
- **受控集成测试：** 在可读取最终内容的本地网页测试编辑器中检查输入结果，并验证 Enter、Shift+Enter、Tab、焦点与取消键拦截。该测试只证明受控编辑器行为。
- **目标人工测试：** 在用户可合法操作的学习通作业与考试代码编辑器中，用不提交的短样本核对最终文本与取消行为；记录浏览器版本、页面类型和所选模式。任务不自动运行代码、保存或提交答案。
- **构建与回归：** 在目标项目目录运行 `swift test`、`swift build`，并核对现有剪贴板捕获、自动捕获、倒计时、延迟和权限引导仍可用。

## 7. 项目约定与边界

**现有结构：** `Sources/TypeClipboardApp/` 放 SwiftUI 界面、ViewModel 与按键引擎；`Sources/TypeClipboardApp/Resources/` 放资源；`Tests/TypeClipboardAppTests/` 放 XCTest；根目录有 `README.md`、`GUIDE.md`、`Package.swift`。

**构建命令**（在 `/Users/Admin/Desktop/TypeClipboard` 执行）：

```bash
swift test
swift build
./scripts/build-app-bundle.sh
```

**代码风格：** 延续现有 Swift 6.2 风格：明确命名、小而可测试的职责、主线程 UI 状态使用 `@MainActor`，异步任务显式处理取消。例如：

```swift
@MainActor
func cancelTyping() {
    guard isTyping else { return }
    typingTask?.cancel()
}
```

**必须做到：** 不记录或上传剪贴板/代码正文；输入模式与语言设置只保存必要偏好；权限不足时给出明确引导；文档与实际行为同步；保留已有功能。

**范围外：** 自动识别网址、浏览器扩展、读取或逐字校验网页最终内容、自动提交/运行代码、绕过网页限制的承诺、无实际问题依据的速度优化。

**平台边界：** 系统保留按键、受保护输入框或网页自行拦截/改写按键时，应用可能无法观察或保证结果。此时应如实报告已知失败；无法检测的目标端变化由用户核对。
